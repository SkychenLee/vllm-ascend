3. Cube runtime guard、数据契约与回退

源码：cube_moe.py:185 prepare。
  - slot 已加载，整数，且位于 A weights slot 范围。
  - X contiguous BF16 [R,4096]，同 device；6144<=R<=98304。
  - counts INT64 [32]，同 device，group_list_type==1（count mode）。
    type=0 prefix mode 不支持，不做猜测转换。
  - 同一个 scratch NPU stream；其他流 prepare 返回 None。
  - CPU plan 要求 32 个非负 counts；512<=sum(counts)<=R；tile 数<=1567。
这里 R 是 routed buffer capacity，可能含未初始化/padded 尾部，sum(counts) 才是有效行数。
不满足这些条件返回 None，继续原 BGMV shrink。prepare 之后如果输入 identity、
generation、loaded slot、combined index shape/type/device 或 stream 变了，则明确
ValueError；不是无声 BGMV 回退。

prepare 中 counts.cpu().tolist() 是实际 256 B D2H 与 CPU 同步，也会等待前面的 NPU
生产 counts 工作。随后 CPU 建 tile plan，并向持久 metadata 复制一次 INT64 [S,3]。
最大实际 plan 1567*3*8=37608 B；分配容量是 1568*3*8=37632 B。
必须把 readback、CPU plan、H2D 以及各 gather/scatter 计入 Prefill 总时间；
只量 BMM 会夸大收益。host readback/CPU branch 是这一路不允许 graph capture 的原因。

数据契约：上游 AllGather InitRouting 生产 expert-major 有效 source 前缀和 expert count，
同一个 adapter 覆盖全 batch。combined indices 只检查 [R]、INT64、device，
成功路径不再逐值检查它；依赖上述 producer/adapter invariant。

4. Cube packing、tile/wave 与缓存生命周期

输入 A_gate/A_up：两个相同形状 contiguous BF16 [slots,32,16,4096]。
每层 packed：BF16 [32,4096,32]，gate/up 转置后 rank16+16 拼接。
cache key=(slot,generation,storage pointer/offset/shape/stride/dtype/device)。
set_lora/reset_lora hooks invalidate；set 成功后 mark_loaded；切 slot 或 generation
导致重新 pack。routing 是每 batch 重新计划，不缓存。直接绕过这些 hooks 原地改 A 值
不会被 key 检测；代码没有 content checksum/_version guard。

TILE_ROWS=64，WAVE_TILES=224，MAX_ROUTED_ROWS=98304，MAX_PLAN_TILES=1567。
每 expert count 切成最多 64 行 tile，source offset 是 count 的 expert-major prefix。
S=sum_e ceil(count_e/64)，最大 7 waves。算法顺序：
  1) 两个 FP32 output [R+1,16] 只在开始 zero 一次；R 行作为无效 padding sink。
  2) 每 wave 取最多 224 个 tile，形成 [wave,64] source/valid。
  3) index_select X 得 BF16 [wave,64,4096]，无效行 mask 为 0。
  4) index_select packed A 得 BF16 [wave,4096,32]。
  5) aten.bmm.dtype_out 得 FP32 [wave,64,32]。
  6) rank 两半分别 scatter 至 FP32 [R+1,16]，无效行写 sink；返回 [:R]。
同 stream 保证 scatter 完成顺序先于下一 wave 覆盖 arena，无 wave 间主机同步。
一旦 routing 成功接受，全部 waves 都是该 Cube 路径；没有 overflow wave 转 BGMV。
函数名 shrink_pair 的 bgmv 参数在成功路径不使用。

只替换 routed W13 gate/up 的两个 A shrink。W13 B expand、W2 A/B、共享专家/普通
LoRA、base W8A8 grouped matmul、激活/量化及通信都保持各自路径；不是整层 Cube。
Punica 额外要求无 input_scale、非 fully_sharded、非 fuse_swiglu、A slices=2；
不满足时不接受 cube_pair。源码：punica_npu.py:499。

6. 历史 SGMV/BGMV 与独立 grouped INT8 Prefill 路径

历史内核文件：csrc/kernels/{bgmv_shrink,bgmv_expand,sgmv_shrink,sgmv_expand}.cpp。
它们是向量 Cast/Mul/Reduce 路径，不是 Cube kernels。
  - BGMV：per-token INT64 adapter indices，负数跳过 delta。
  - SGMV：per-sequence adapter ids + sequence lengths。
  - shrink：FP16/BF16 X/A -> FP32 rank outputs；输入/权重 cast 后向量乘归约。
    TILE_LENGTH=11776；H 超过 tile 时分段累加。
  - expand：FP32 rank input，FP16/BF16 B，cast 回 FP16/BF16 output 并加已有值；
    BGMV 核支持 rank8/16/32/64。
  - inactive 索引不写 shrink，所以 Python 原路径用零初始化 shrink buffer。
普通 dense/shared LoRA 按 Punica.is_prefill 在 SGMV/BGMV 之间选择；routed MoE 路径
默认直接 BGMV，即使是 Prefill，只有 Cube 接受时替换 W13 A shrink。
310P 或 max_lora_rank>=128 时 Punica 选择 upstream torchops fallback。
历史真实 Decode graph 也有 SGMV（shared/dense 的 captured metadata 分支），
不能把所有 Decode LoRA 都称为 BGMV。

另一个历史开关 VLLM_ASCEND_MOE_LORA_GROUPED_PREFILL，默认 0，import 时决定
grouped_prefill.ENABLE_GROUPED_PREFILL。源码：grouped_prefill.py:11,44。
此路径是 fully_sharded=True 且 use_ep=False 的独立 INT8 路径，与上述 EP Cube 不同：
  - INT8 hidden_states on NPU，w13_lora_a_packed 存在。
  - 8192<=R<=2^24，R>=groups*8，0<groups<2^24。
  - 0<H<=4096，H%64==0，2*local_rank*H<=16384。
  - full LoRA rank in {8,16,32}；0<I_partition<=256，I_partition%32==0。
  - 三个 native ops 已注册：bgmv_shrink_int8_pair_grouped、
    moe_lora_expand_swiglu_quant_pair_grouped、bgmv_expand_grouped。
GPU FP32 exact-range keys 排 combined expert/adapter index，负数/越界最后保留 -1；
argsort(order.float()) 得 inverse。无 counts D2H，fixed shapes 可 graph replay。
配套 C++ 注册在 csrc/moe_lora_int8.cpp；包括独立 tiled B expand。
current TP8+EP8、非 fully_sharded 的目标不能命中 GROUPED_PREFILL；不能用它的
存在说明 EP Decode 已经 grouped/Cube 化，也不能由此给出非 EP 整网吞吐数字。

8. MTP persistent buffer 问题与本轮实现

源码：deepseek_v4.py:1085 分配、1097 helper、1189/1191 SP/非SP调用、1331 getter。
buffer 始终分配 [Bmax,hc_mult*H]，model dtype，稳定地址；即便 spec=None 仍 stash。
目标 Bmax16384、hc_mult4、H4096：BF16 [16384,16384] =536870912 B=512 MiB/rank。
当前改变写入方式，未减少这512 MiB持久分配。

新开关 VLLM_ASCEND_OPTIMIZE_MTP_BUFFER_COPY，strict 0/1 默认 0。
flag1 在初始化持久 INT64 arange(Bmax)[:,None]，[16384,1] 为131072 B=128KiB/rank。
flag0 field=None，没有这一额外 tensor。

helper 顺序与 fallback：
  1) 必须二维且 width==buffer width，否则 ValueError；n>capacity 同样在写前报错。
  2) n==0 返回，避免空 NPU operator。
  3) flag0/rows=None、源/目标 dtype 不同、device 不同或目标不为 FP16/BF16时，
     buffer[:n].copy_(source)，保留原 copy_ 的转换语义。
  4) 其他条件使用 npu_scatter_nd_update_(full_buffer,rows[:n],source)。
同 persistent pointer、已有 aliases 与尾部 [n:] 完整保持，更新前 n 行。
SP 分支仍先 all_gather flattened residual，再去 pad，调用同 helper；非 SP 直接
flatten(1) 调同 helper。没有变更 all_gather、hc_head、getter 或 speculative 分流。

原因证据分层：
  - 旧 rank0 graph 两个巨大 TensorMove 每步共1.6904567ms；形状flat268435456 与
    [16384,16384] BF16。旧模型 cached computation_graph 标明对应 persistent MTP
    buffer slice-copy；小摘录 ../evidence/2026-10-06/profiles/old_mtp_capture_excerpt.txt。
  - 普通 raw NPUGraph 小 partial copy9.32us、scatter16.64us，并不重现问题。
  - torch.func.functionalize 单独测试也不是实际后端归属证据。
  - 实际 npugraph_ex compiler，force_eager=True、inplace_pass=False、
    clone_input/clone_output=False，局部 view mutation 被 functionalization 展开，
    每步两个完整512MiB buffer copies；builtin native scatter 保持真正 in-place。
因此1.69ms属于这个已观察到的编译图条件，不能声称所有 copy_ 都昂贵或所有配置
都必得同样整网收益。原隔离函数含 source+1 baseline1726.29us、scatter22.59us，
而下面更强证据直接调用实际 production helper。

10. DSpark/no-spec skip 仍为待实现候选，以及 V2 getter 风险

当前 DeepseekV4Model 不论是否 speculative 都 stash；MTP flag只改写入算子。
get_mtp_target_hidden_states 返回 persistent pre-hc_head residual；本轮没有让它为None。
DSpark target 的 aux layers 收集 hidden_states.mean(dim=1)，draft model
deepseek_v4_dspark.py 有自己的 main_proj/main_norm、layers 与 hc_head，
combine_hidden_states 合并目标 aux；draft没有 _mtp_hidden_buffer/helper/getter。
这不自动证明 target buffer可跳过，因为 runner 还有 generic consumer。

V1 worker/model_runner_v1.py:1575 位于 speculative 分支，用 getter 后只有
method==mtp 且 result is not None 才替换 hidden_states；无 spec不消费该 getter。
V2 Ascend NPUModelRunner 继承 upstream GPUModelRunner，当前容器上游
{upstream_repo}/vllm/v1/worker/gpu/model_runner.py:599 和1463：
  if hasattr(self.model, 'get_mtp_target_hidden_states'):
      pre_hc_hidden_states = self.model.get_mtp_target_hidden_states()
      spec_hidden_states = pre_hc_hidden_states[:hidden_states.shape[0]]
没有 None guard，也没有按 mtp method 限制；Ascend V2 DSpark speculator 将
last_hidden_states/aux_hidden_states 继续传给 superclass。因此未来若把 DSpark/no-spec
